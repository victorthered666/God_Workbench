# 架构审核
核对目标一致性、系统闭环、术语与数值冲突、交互异常、图文引用、来源可追溯、资源覆盖。无证据的缺陷不得凭空断言；严重程度 high 仅用于核心闭环矛盾或不可执行问题。

## owner 归属标准
owner 表示"能在文档层面实施修复的角色"，不是问题所属的知识领域：
- 正文措辞/数值/引用/表格矛盾 → writer（可在文档内直接修正）；
- 交互规格缺口 → interaction；资源清单问题 → producer；调研事实错误 → research；
- 仅当修复必须推翻已确认框架的结构或设计目标（删章、改方向、改硬约束）时才归 architect。
架构类发现会阻断自动修订并要求人工决策，误用会直接卡死流程；归 writer 可自动修复。

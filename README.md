# 神的使者 · 游戏策划文档 Harness

一个本地运行的**原生 Rust** 多 Agent 游戏策划工作台。将调研、框架确认、正文撰写、交互补图、资源拆解、架构审核与资料归档放入同一条可追溯流水线。

**代码栈已从 Python 完全迁移为 Rust**：HTTP 服务（Axum/Tokio）、SQLite（rusqlite）、Agent 编排、图片处理（image/imageproc）、DOCX 导出（docx-rs）均为原生实现，不再需要 Python、Node 或 `.venv`。旧 Python 实现已从仓库移除，如需追溯可查看 Git 历史早期提交。

## 启动

Windows 已安装 Rust 工具链（1.85+）时：

```powershell
.\run.ps1
```

首次运行会执行 `cargo build --release`（约几分钟），随后打开 `http://127.0.0.1:8765`。

手动构建与启动：

```bash
cargo build --release
./target/release/gdd-harness.exe
```

不要绑定 `0.0.0.0` 或暴露到公网。服务写接口要求页面内存中的随机会话令牌，重启后旧页面应刷新。

## 配置密钥

在网页右上角 **Agent 设置** 中配置，或在启动进程的环境中设置：

| 用途 | 环境变量 | 说明 |
| --- | --- | --- |
| 模型与 DeepSeek 网页搜索 | `DEEPSEEK_API_KEY` | 默认 Base URL `https://api.deepseek.com` |
| 豆包图片搜索 | `WEB_SEARCH_API_KEY` | 与个人版/Agent Plan 开通方式有关 |

每个 Agent 可独立设置模型、Base URL、密钥变量名、温度、最大输出 Token、Skill 和系统提示词。`writer` 的 `vision_model` 默认为 `deepseek-flash`，用于观察真实图片后生成标注位置。

未在界面保存密钥时读取环境变量；界面显式保存的本地密钥优先。密钥使用与旧版兼容的 Fernet 格式加密保存到 `data/secrets.json`（原生 AES-CBC + HMAC-SHA256 实现），不会回显或导出。旧 Python 版保存的密钥无需重新录入。

DeepSeek 网页搜索与抓取可能产生费用；豆包图片检索可能有免费额度或套餐限制，以服务商页面为准。创建项目会立即发起调研，工作流不会用真实调用做无提示"连通性测试"。

## 使用流程

1. **新建项目**：输入设计目的、参考对象，选填平台和受众。
2. **调研策划**：通过 DeepSeek 搜索/抓取重点资料，区分事实、推断和建议。可直接编辑 JSON 或提交反馈，最后必须手动确认。
3. **架构策划**：形成带章节职责、要求、图示和验收重点的框架。修改或反馈后，手动确认。
4. **文档执行策划**：细化机制，使用豆包检索参考图，实际下载后由视觉模型标注；自绘核心流程图。
5. **交互策划**：补入口、输入、状态、反馈、异常和空状态，生成带编号线框图。
6. **初级项目经理**：将功能、美术和音效拆成带来源章节、依赖、优先级和验收标准的表格。
7. **架构审核**：问题按角色分派。最多自动修订 3 轮；仍不通过转人工。涉及已确认调研或框架的问题也转人工，不绕过门禁。
8. **导出**：只有审核通过才可生成定稿 Markdown、DOCX 与 ZIP。

"修改文档"先分析影响范围，确认后才重做必要阶段。直接编辑 Markdown 后需重新执行资源拆解和审核。页面"版本与日志"保存历史产物与执行事件。

## 输出结构

```text
outputs/<文档名称>-<项目短ID>/
  <文档名称>.md
  <文档名称>.docx
  <文档名称>-v<修订号>.zip
  assets/images/          # 下载原图、标注图与标注文本
  assets/diagrams/        # 自绘流程图、线框图
  research/               # 调研与检索证据
  reviews/                # 审核及版本历史
  versions/               # 阶段快照
  manifest.json           # 素材来源、批准记录、文件哈希
```

文件名中的非法字符会替换，并追加项目短 ID，避免覆盖同名项目。

## 资料与图片边界

- DeepSeek 负责网页证据，不宣称支持图片搜索。
- 豆包图片搜索单次最多 5 条，全局并发限制为 5；失败保留错误，不伪造图片。
- 下载只允许公网 HTTPS；检查 DNS、最多 3 次重定向、12 MiB 大小、8192px 像素与真实图像格式，限制项目内路径。
- 标注坐标由视觉模型观察已下载图片产生。模型仍可能选点不准，交付前需人工核查。
- 可检索、可下载不等于拥有版权。参考图仅用于研究；公开或商业使用前自行核查授权。
- 网页预览使用 Ammonia 允许列表清理（标签、属性、URL scheme 白名单）；图片通过本机受限接口读取。

## 数据与故障恢复

SQLite 位于 `data/gdd.db`，保存项目、版本、事件、运行快照、证据和设置；Agent 会话也持久化。版本写入使用 `BEGIN IMMEDIATE` 事务，避免多请求竞争。服务重启会把未完成任务标为中断，**不自动重发外部请求**。检查日志后可从当前阶段恢复。

若模型输出截断或结构校验失败，阶段明确失败，不会将半成品标为已完成。运行中的 HTTP 请求不能可靠取消；取消按钮不会假装撤回已经发出的请求。

可通过环境变量改变数据/导出目录：

```powershell
$env:GDD_DATA_DIR = "D:\GDD-Data"
$env:GDD_OUTPUT_DIR = "D:\GDD-Outputs"
$env:GDD_PORT = "8765"
```

## 测试

```bash
cargo test
```

9 项测试覆盖：状态机与人工门禁、三轮审核转人工、旧 SQLite 数据读取、Fernet 密钥兼容、文件名净化与 UTF-8 截断、极限标题换行、视觉图片负载上限、HTTP 契约（设置字段、表格渲染、导出门禁）。

测试使用临时数据库和 Mock HTTP，不读取真实密钥、不调用真实模型或搜索服务。

内存安全限制见 `docs/memory-safety.md`；图片 API 调研见 `docs/image-api-research.md`；验证记录见 `docs/verification.md`。

## 关键目录

- `src/`：Rust 后端全部模块。
  - `agent/`：独立角色会话、模型循环、工具权限、视觉标注。
  - `workflow.rs`：状态机、人工确认、修订、三轮审核。
  - `tools/`：DeepSeek 与豆包 API 契约、有界流式响应。
  - `media/`：图片下载、标注、流程图、线框图。
  - `export/`：DOCX（docx-rs）、资源附录、归档与清单。
  - `http/`：路由、本机写入令牌、HTML 允许列表清理。
- `config/agents/`、`agents/`、`skills/`：可单独修改的默认配置、提示词与技能。
- `web/`：复用的原生中文前端（含每个角色的字符动画、耗时显示与全自动流程开关）。
- `docs/`：内存安全、验证记录、图片 API 调研。
